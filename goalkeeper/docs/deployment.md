# 部署计划：32×H20 + 8×RTX 5090

用户已确认资源数量，目前无法提供 SSH。因此没有连接集群、运行 GPU 训练或修改远程环境。本文件是后续部署步骤，不是已完成的任务记录。

## 分工与启动次序

| 阶段 | H20 | RTX 5090 | 放行条件 |
|---|---|---|---|
| 环境验证 | 1 张加载主干及小头 | 1 张运行单个训练场景 | 官方版本、动作契约、reset、视频、显存均正确 |
| 数据试采 | 1–4 张特征/候选推理 | 先 1 卡，再扩至 8 卡各 1 个进程 | 分支状态恢复后重复执行误差可接受，标签对齐 |
| 首轮实验 | 1–4 张小头，其余按需给主干/对照 | 最多 8 卡并行，实际并发通过压测确定 | held-out 数据上可预测回退，闭环干预有正收益 |
| 扩大实验 | 主干可用 24–32 张；另按需排队做对照 | 8 卡跑固定的任务/实例清单 | 通过匹配计算量的诊断实验后再扩大 |

不用把 32 张卡都投入小头训练，也不假设每张 5090 可以同时稳定跑多个大场景。机器拓扑、CPU、内存、磁盘和网络未知，不能把 GPU 数换算成承诺工期。公开数据集约 3TB；特征缓存需要额外预算，应先测每分钟演示的实际占用。

策略服务可在 H20，仿真客户端在 5090。当前协议每个动作步发送图像，即使服务内部缓存动作，也应测 RPC 网络占比。正式吞吐优化可能需要共享主干批处理，但当前逐连接的小头和逐任务服务只是正确性入口。

在训练环境和仿真环境分别运行并保存输出；命令只读取环境信息。

```bash
python scripts/check_environment.py \
  --behavior-root /path/BEHAVIOR-1K --openpi-root /path/openpi \

```

仿真固定官方 v3.9.2 及它要求的运行时。RTX 5090 的驱动、渲染和依赖兼容性由实际 smoke rollout 确认。安装代码时保留上游锁定环境，先检查依赖冲突，再安装本包；不要未经验证就升级整套 OpenPI/OmniGibson 依赖。

## 首次验证与数据

1. 用官方提供的 `turning_on_radio` 基线跑一个训练实例和一个按官方规则指定的测试实例；记录真实 state/action 维数、顺序、相机、控制器、normalization、超时、随机种子、软件 commit。以权重对应的官方服务结果为起点。
2. 再跑本仓库 `baseline` 前缀控制；它和 Comet 的 temporal ensemble 不同，任何性能差异先在这里解释。
3. 在训练实例重放 demonstration，离线采集 goal truth；可见性标注不可靠时标 -1。不同相机保持独立数组。用 `export` 构造 K=1 小样本，再进入 H20 单卡 head 训练与独立校准。
4. 实际分支采集器需接入现有仿真代码后实现并验证。一个训练根状态的 K 个前缀执行分别得到标签，全部共享 `group_id`。在这个环节跑通前，不要宣称已训练反事实排序。
5. `shadow` 校验候选、标签、干预记录和开销，之后在诊断任务上启用 `rerank`。小头不能使用测试集标签训练。

`scripts/train_head_ddp.sh` 以 4 节点×8卡为示例；真实拓扑不是这个布局时设置 `GK_NNODES/GK_GPUS_PER_NODE`。32 张卡跨节点 NCCL 仍需 GPU 实测。本地已验证的是两个 CPU 进程的 Gloo 训练与同步。

## 任务覆盖与最终提交

已下载官方 gallery 的 100 个任务在 v3.9.2 中的公开 `problem0.bddl`。当前编译器接受 77 个，明确拒绝 23 个，详情在 `bddl_coverage.json`。这不是 77 个任务已能完成，更不是逐场景实例绑定的认证。

限制来自通配符对象域、配对量词和 DNF 组合规模。通配符必须保持集合语义，不能把 `cabinet_*` 当作一个具体柜子。配对量词的求值和 ground-option 展开还需核对一致性，不应仅按英文名称实现“完美匹配”。后续需要扩展保留量词的表示，或使用允许的公共绑定信息；不能在评测时通过 simulator object scope 补齐。

对于本轮不支持的任务，配置显式设为 `baseline` 即可通过未经编译的静态任务上下文运行主干；服务会输出禁用小头的原因。`rerank` 模式仍拒绝这些定义，避免静默改变目标。全量对比保留全部 100 任务、包含这些 baseline 任务，分母不变。

官方提交页写完整规模 100×10，而当前 v3.9.2 代码公开/隐藏 split 各有 20 个可索引实例，CLI 默认只跑 index 0。**因此不要把默认命令或随意挑十个实例当完整提交。** 实际 `expected.json` 应使用举办方规定清单，instance ID 通过官方解析器得到；最终按最新比赛要求核对数量。这个区别是源码与网页的实际核查结果。

保存完整原始 JSON、视频、wrapper、机器人配置和权重 hash。Docker 提交必须实测单张 24GB 显存；另一种 IP 方式要求至少 50 个端口。已有 8 张 5090 用于自评，不等于已经满足任何一种正式提交方式。
