## 每轮流程

```
第 k 轮：
  闲时 5090 × 32      用第 k-1 版策略采样 64 条轨迹（实例 1–16 × 每实例 4 条，每张卡 2 条，约 40 分钟）
                      每条轨迹采完就写回执（含策略哈希、奖励契约、sha256）
        ↓  回执收齐，或已收齐 95% 且其余回合已放弃
  训练卡 × 4          H100（share-cluster，n6ls.iu.i40.4，NCCL）或 5090（gloo）
                      从第 k-1 版的 actor、critic 和优化器状态继续，17 步更新（约 10–15 分钟）
        ↓  发布第 k 版策略
  闲时 5090           评测第 k 版（在训练阶段和下一轮采样的空档里进行），与原模型配对比较
```

- 采样卡数量是 2026-11-03 按用户要求定的 32 张（原来是 16 张 × 每张 4 条，约 75 分钟）。
- 任何作业都不会空占 GPU：采样作业跑完分到的回合就退出；训练作业等本轮数据齐了才提交，训练完就退出。

## 训练循环（learner）

`runtime/` 在上一次实验的运行时基础上做了以下改动。不开启这些配置时，行为与原来完全相同。

| 改动 | 说明 |
|---|---|
| **前缀缓存**（2026-11-03） | 冻结的 VLM 前缀（SigLIP + Gemma-2B，3×256 个图像 token 加 512 个文本 token）占每次前向计算量的 98%，一轮之内是常量。每张卡在本轮开始时算一次，只算自己负责的行（行号 % 卡数 == rank），存进 host pinned 内存（每卡约 76 GiB）。之后的 KL 检查、回放校验、分批梯度和 critic 刷新都直接读缓存。实测（`../prefix_cache_probe_20261103/RESULTS.md`）：同样分批时输出与重算逐位相同；梯度相对差 2.5e-5，现有分批噪声是 7.8e-4；KL 前向快 30–40 倍，梯度快 7 倍。内存不够时全部卡一起退回不缓存 |
| 按归属分配梯度行 | 开启缓存时，每步的行按 `i % world == rank` 分给各卡，也就是各卡缓存的那些行。全局梯度和不变，只是浮点求和顺序不同 |
| 每步全量 KL | 有了缓存，全量 KL 每次约 7 秒，所以每步都做全量检查，阈值 0.01。抽样 KL 不再使用，它在平台期会把 lr1e6 提前停在第 8 步 |
| checkpoint 每 4 步 | 每个通过的状态都作为内存里的回滚锚点；每 4 步和最后一步才写盘。被回收时最多重算 3 步，有缓存时约 30 秒 |
| 分批梯度 | 每个 microbatch（4）只做一次前向，再按行切开算损失。启动时的一致性检查用分批路径（带缓存）对照串行逐行路径（不带缓存） |
| 容差回放校验 | 训练卡重算采样卡上的 log 概率，概率比误差 ≤1%、平均 KL ≤1e-5 即通过。原始采样 log 概率不会被覆盖 |
| on-policy 强制 | 回执里的策略哈希必须等于本轮起点策略的哈希。回执留在 AFS，计划里只带规范化摘要 |
| H100 启动 | GPU 型号白名单从计划读取；纯训练作业在节点没有 EGL 库时跳过图形配置 |
| 计时与统计 | 记录每步的快照、梯度、KL、checkpoint 耗时，各准备阶段耗时，以及每张卡的缓存命中、重算和不一致次数（`prefix_cache.json`） |
| 精简打包 | 训练代码包用 AST 去掉注释和文档字符串；不再打包 `experiment.py`（唯一用到的 `seed_all` 已内联）。启动命令约 62K 字符，低于 64K |

**训练卡数值精度**：learner 用严格 FP32（`matmul_precision("highest")`，不开 TF32），这样才能和采样卡的 log 概率对上。所以 H100 的 Tensor Core 用不上，严格 FP32 下它并不比 5090 快。

## 闲时卡回收

| 作业 | 被回收时的处理 |
|---|---|
| 采样 | 已完成的回合各有回执（AFS 上一份，结果包里一份）。未完成的回合归档后重新分配；要先确认旧 worker 已退出，避免两个进程写同一个目录 |
| 训练 | 从最近写盘的 checkpoint 断点续训，最多损失 3 步。续训时会重建前缀缓存，并跳过 critic 预热、回放校验和一致性检查 |
| 评测 | 每个作业只跑一个回合，重提即可 |

重试规则：

- **被回收不计入失败上限**（每项 3 次），只计入总次数硬上限（10 次）。
- **怎么算被回收**：平台状态为 SUSPENDED；或者作业因 SIGTERM 中止，且运行时长明显短于自身时限。接近时限才中止的算超时，是真实失败。
- **提交失败**：`jobs copy` 失败、平台查不到作业时，记为 NOT_CREATED 并重试，不会卡住调度。2026-11-03 评测实验曾因此停滞 3.5 小时。

| | 第 1 轮 | 第 2 轮 | 第 3 轮 |
|---|---|---|---|

- **最终评测**（第 3 版 vs 原模型，实例 301–320 × seed 0–9，配对）：
  - 成功率 140/199（70.4%）→ 148/199（74.4%），差 +4.0pp，95% CI −4.3 ~ +12.4pp；转败为胜 40 局、由胜转败 32 局，McNemar p = 0.41。
  - 平均分 0.778 → 0.808，符号翻转检验 p = 0.38。
  - 结论：方向为正，但不显著。
- **缺 1 局：** 312/s9 的评测跑完了，但作业以 FAILED 结束（stage = evaluation_complete），被判为不可重试，没有补跑。
- **资源：** 评测 65.0、采样 54.9、训练 6.7，合计 126.6 GPU·小时（上限 240）。
- **运行中的修改**（`launch_amendment_1..5.json`）：
  1. 标准卡只给训练；
  2. H100 训练卡单独计数；
  3. 只评测最后一版（200 局）；

  5. 修复启动时的临时文件冲突。
- **更新量很小：** 每轮只用了约一半的 KL 预算。第 2、3 轮沿用了上一轮的 Adam 状态，前几步只有第 1 轮的约十分之一。3 轮累计的"学习率 × 步数"只相当于模仿学习在峰值学习率下走 20 步。

## 资源前提

- 标准额度每人 4 张：SkyWM 训练占 2 张。训练作业的配额策略是 `reserved_if_free`：标准额度有 4 张空闲时用标准卡，否则用闲时卡（仍可断点续训）。
- 每张训练卡的缓存需要约 76 GiB host 内存，4 卡 H100 节点有 960 GiB。5090 节点内存不够时会自动退回不缓存，结果正确但慢。
